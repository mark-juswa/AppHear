The refiner computes 21×XYZ and world XYZ, but Android returns only XY plus presence/handedness/validity; Python `RefinedHand` exposes `raw_z/world_xyz` but raw-v1 does not persist them. No raw-v1 palm normal, RGB crop, intrinsic calibration, reliable 3D depth, per-joint refiner confidence or temporal identity tracker is available. Missing Python geometry/ROI is NaN with masks; Android uses zero arrays for absent geometry/ROI with false masks. Consumers must honor schema and masks, not infer validity from coordinates. Android's carrier itself has no schema string; a future external subscriber must explicitly bind/validate a versioned envelope. The V2 adapter validates schema and image semantics.

**378 is a segmentation representation, not an alphabet contract.** `pipeline/perception_vnext/segmentation/learned_features.py:FEATURE_BLOCKS/derive_causal_segmentation_features` defines normalized hand XY (84), validity (42), proposal support (42), presence/validity/observed/proposal flags (8), ROI (6), body XY/support/validity/availability (33), dt (1), hand deltas/validity (126), ROI deltas/validity (8), body deltas/validity (24), observed/proposal transitions (4). Deltas are displacement, not dt-divided velocities. S2 learned PRE/ACTIVE/POST on word-event supervision; it has no demonstrated per-letter boundary behavior.

**V2 is a word representation, not verified sufficient for A–Z.** `pipeline/perception_vnext/recognition_schema_v2.py:derive_selected_features_v2/temporal_view_v2` mirrors Kotlin. Groups are left/right hand 130 each, body 36, inter-hand 7, left/right motion 21 each, inter-hand motion 3, time 2. Hand-local bone directions, signed angle sin/cos, fingertips, body-relative wrist/palm axes, support/presence/masks and timestamp-derived motion are available. Orientation normalization and dependence of some channels on a valid body reference may remove useful letter distinctions; neither 2D separability nor moving-letter coverage is established. V2's completed-event normalized progress also should not silently become a causal letter input.

**VERIFIED reusable seam:** the freshly built `PhoneRawObservation` in `Candidate01FrameAnalyzer.analyze`, immediately before `session.consume`. It already exists for every processed frame. **RECOMMENDATION:** future bounded read-only subscription with an immutable/deep-copied envelope; no refiner/pose re-execution. There is no public general-purpose hand subscriber today. Overlay output is incomplete for a full raw contract and on the UI delivery path; the materialized word window is too downstream to assume suitable letter timing. Array fields are mutable despite Kotlin `val`; never share them with a mutating/asynchronous consumer without ownership protection.

## 3. VERIFIED infrastructure; proposed future integration

`RecognitionActivity` creates a single `cameraExecutor` and separate `a1ShutdownExecutor`. `start()` constructs `PhoneProductionSession` and Candidate01 on `Dispatchers.IO`. `Candidate01FrameAnalyzer.analyze` is synchronized, runs on CameraX's single analysis executor and always closes `ImageProxy`. DWPose/refiners/S2/completed-event word inference are sequential there. `PhoneProductionSession` has no executor of its own; synchronized `consume/reset/clear` protect state, not parallel inference throughput. UI callbacks use `runOnUiThread`. Pause/rebind resets temporal state; destroy stops CameraX, joins the camera executor before closing native/interpreter owners, and avoids close on a failed join.

There is no universal multi-model scheduler. Existing loaders provide patterns: `HandRefinerRunner` maps assets and uses CPU/XNNPACK 2 threads; `PhoneS2Runner` and `RecognitionV2LiveRecognizer` use CPU/XNNPACK 4 threads, NNAPI OFF, hash/schema/shape checks and owned buffers. Legacy `pipeline/recognition/Recognizer.load/infer` plus `ModelContract` use the older 258 schema and are not the active normal backend. Candidate01 already coexists with multiple inference models; adding another interpreter is structurally possible without another camera/perception stack, **not device-proven safe**. Future load must be async; one serialized owner per interpreter, bounded work and lifecycle join/close. Serial execution adds camera latency; concurrent execution adds CPU contention and stale-result risk. Neither is free or authorized here.

**RECOMMENDATION — future explicit mode seam:** introduce a coordinator at observation dispatch/session ownership, with `WORD` selecting the unchanged word session and `FINGERSPELL` selecting a separate temporal letter session/`SpellingBuffer`. Keep the mode fixed for an active event/letter run; defer changes until an agreed quiescent boundary. Use mode + camera/session generation + event identity on every result; reject stale work after mode/lifecycle transitions.

**Commit guarantee:** the coordinator must grant one exclusive output owner. WORD may reach existing SentenceBuilder; FINGERSPELL may reach only SpellingBuffer. Letter delivery must preserve repeated letters using distinct event IDs, rather than equal-label dedup. The current word session commits *internally* in `consume`; suppressing its displayed return value does not suppress `sentence.add`. A future design must stop delivering committing observations to the unselected word owner, or introduce a separately approved commit boundary while preserving WORD behavior. Event IDs restart on reset, so IDs alone are insufficient across generations. Shadow alphabet/routing evaluation must have no product commit capability. Never compare maximum word/alphabet softmax scores to choose a mode; independent classifier scales/label spaces are not comparable.

## 6. RECOMMENDED minimum standalone training contract

- **Source:** unchanged current-frame Candidate01 raw-v1 evidence from original, hash-linked video; no second vision stack. Bind schema, image semantics, anatomical slot convention, preprocessing/model hashes, timestamps and all masks explicitly. Start with information common to Python/Android; Python-only handedness/Z/world must not be silently trained as Android input.
- **Conceptual input:** variable-time sequence of both hands' `[T,2,21,2]` XY plus joint/group/ROI/support masks, presence and real timestamps/dt; retain available body evidence separately for framing/trajectory context. Derive scale-normalized wrist-relative finger geometry while retaining image/palm orientation and wrist/fingertip trajectories needed for movement. Use zero only with validity flags; distinguish absent observations, padding and uncertain physical visibility. Named tensors or a separately versioned `[T,D]` contract are alternatives to be frozen after collection/parity review. Do not prescribe D, T, an encoder, V2's 96, or S2's 61 yet.
- **Targets:** stable label order A–Z + OTHER, with schema/normalization/class-order manifest. Temporal sequences must include full moving letters, hold/release, adjacent-letter transitions, different rates, repeated letters, partial/aborted attempts and natural names/words with reviewed transcripts. Keep boundary/annotation uncertainty separate; OTHER is not a CTC blank or spelling end-of-word command.
- **OTHER:** human-reviewed idle/no hands, visible hands doing ordinary actions, word signs, non-alphabet gestures, partial/ambiguous non-letter attempts, occlusion/perception failure and appropriate inter-letter non-letter intervals. Include difficult letter-like negatives. Do not label every transition OTHER blindly, or relabel a real letter OTHER because perception missed it. Quarantine uncertain intervals; annotate intended letters separately from observation quality. Existing word/no-sign data may contribute only when rights and existing TRAIN roles permit; never pull protected word/phone evaluation into OTHER.
- **Splits:** resolve real human identities across device IDs, sessions, mirrors, files and relocated copies before TRAIN/DEV/protected TEST assignment.
