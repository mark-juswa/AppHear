# Context Assist deferred issues

Status: OPEN for the deadline advisory feature. Raw recognition and Hear/TTS remain authoritative. These issues are retained for later work; none is solved by this UI milestone.

| Issue | Evidence | Current impact | Why deferred | Likely future direction | Status |
|---|---|---|---|---|---|
| Recognition and signer generalization | Stage 3 first-pass GO→GIFT, GO→PERSON, TIRED→LIVE2, GOOD→HOT; intended label was absent from Top-5 for these associated events. | Context cannot legitimately recover a concept missing from visual evidence. | Frozen recognition path; five-attempt pilot cannot support model changes. | Separate held-out signer, end-to-end recognition/generalization effort with new signer diversity. | DEFERRED — recognizer/generalization work required |
| Extra committed events | Stage 3 raw GIFT HOME GIVE COME, NO LIVE2 GIVE, duplicate YES collapsed in SentenceBuilder, and T02's long sequence with RIGHT3 twice. T02's event source/timing is uncertain. | Noise can prevent a one-to-one phrase match and can change raw text. | Exact cause is unknown; no event lifecycle tuning in this milestone. | Diagnose event timing, segmentation, re-arm, and sequence noise with controlled evidence. | DEFERRED — event lifecycle / sequence-noise investigation |
| Context prediction coverage | T04 intended YES NEED SLEEP but the cache lacked that exact sequence. | Matcher has no relevant phrase to select even if visual evidence is correct. | Prompt/model remain frozen for a clean deadline implementation. | Measure broader conversation coverage, then consider focused provider changes. | DEFERRED — provider coverage limitation |
| Natural-language semantic grounding | Stage 1.1 and Stage 3 show naturalText adding claims, e.g. “thank you” paired with FAMILY GOOD anchors. | A context-supported sentence can convey more than recognizer anchors prove. | A reliable grounding layer is beyond the current matcher and UI scope. | Represent verified anchors separately from naturalization and evaluate semantic claims. | DEFERRED — grounded naturalization layer |
| Gemini latency | Stage 1.1 desktop median rose from about 1.8 s to 7.9 s, with five requests exceeding the unchanged Android coordinator deadline. | Possible replies may arrive late or not appear; raw recognition remains available. | Current async timeout and fail-open path protect the app; no provider tuning in this milestone. | Measure mobile latency, optimize transport or provider flow under a separate gate. | DEFERRED — provider/mobile latency optimization |
| Cross-signer validation | Stage 3 used one signer; whether their signing was in training or prior tuning is unknown. | No held-out cross-signer end-to-end accuracy or assistance benefit can be claimed. | Deadline UI milestone is software behavior, not validated accuracy rollout. | Pre-register a held-out signer protocol and report end-to-end phrase results. | DEFERRED — held-out signer validation |
| Continuous natural signing | Stage 3 used neutral/READY pauses between concepts. | Behavior during fluid signing and coarticulation remains unknown. | Existing production unit is pause-separated isolated signs. | Test continuous phrases only after the underlying recognition path is ready. | DEFERRED — continuous phrase validation |
| Matcher alignment | Current matcher requires one candidate concept per committed event; it abstained on extra-event phrases. | It cannot generally handle insertions, deletions, or long noisy sequences. | Stage 3 first-pass intended labels were usually absent from Top-5, so aggressive alignment is not yet justified. | Revisit bounded alignment only after repeated visual recoverability evidence. | DEFERRED — matcher improvement |
| Production credential transport | Gemini development key is configured locally and may be embedded in a private debug APK; release hard-disables Context Assist and uses empty keys. | Remote prediction is a development capability, not public production cloud infrastructure. | Backend/proxy work is outside this deadline UI milestone. | Move provider calls behind authenticated backend/proxy or another secure transport before release enablement. | DEFERRED — backend/proxy or secure production transport |

Sources: [Stage 3 pilot report](conversation-phrase-assist-stage3-report.md), [Stage 3 event evidence](conversation-phrase-assist-stage3-pilot.json), and [Stage 1.1 provider evaluation](conversation-phrase-assist-stage1_1-report.md).
