# Conversation-aware phrase assistance: baseline audit

**Historical audit:** the integration decision below describes the original MVP. As of
2026-09-29, Context Assist is shadow-only; see `conversation-phrase-assist-shadow-report.md`.

Baseline: `76d93cecd85bf9f76064d320aa4a5791b5f0704a`. Feature branch: `feature/conversation-phrase-assist-mvp`.

## Production Sign-to-Text trace

- `android/app/src/main/java/com/example/apphear/perceptionvnext/RecognitionV2LiveRecognizer.kt` invokes the frozen `[1,96,350]` recognizer once and returns a 236-element `probabilities` vector and score-sorted `top5` indices. Sorting breaks ties by class index. The manifest `android/app/src/main/assets/phase4a_gate2_recognizer_parity/manifest.json` supplies the verified index-to-gloss map.
- `PhoneCausalCore.kt` (`PhoneCausalEventProducer`) creates the event ID. `PhoneProductionSession.kt` materializes a committed event, invokes the recognizer, selects `top5.first()` as Top-1, enforces increasing IDs with `lastCommittedEventId`, then adds the Top-1 gloss to `SentenceBuilder`. The model scores are currently discarded after this point. The safe read-only evidence seam is this committed `Update`, after the ID guard and before the score vector is discarded.
- `SentenceBuilder.kt` stores a bounded deque of up to 20 gloss strings, collapses consecutive duplicates, and has no event association or utterance-completion method. `Candidate01FrameAnalyzer.kt` sends `FrameResult` to `RecognitionActivity.onFrame`; `RecognitionUiSnapshot.kt` turns the recognition state and raw phone sentence into display fields. Camera analysis runs on a single executor and the Activity posts results to the main thread.
- `RecognitionActivity.kt` Clear clears the raw sentence. Speak starts Android speech recognition for a hearing user's reply and routes the transcript into Text-to-ASL. Hear reads the raw sentence aloud. Hear is the only existing positive action that can reasonably finalize a Deaf response. There is no automatic sentence-end detector or send action. The phrase MVP will match at Hear, keep raw S8 unchanged, then display/speak an assisted result only when the visual matcher supports it.

## Hearing side and shared infrastructure

- `ui/texttoasl/TextToAslFragment.kt` obtains speech through `RecognizerIntent.EXTRA_RESULTS` or typed input via Sign It / IME Done. Both reach `submitInput()`, which calls `AslPhrasePlanner.plan`, stores `lastInputText`, renders the requested text, and plays the local GLB queue. `MainActivity.kt` carries speech captured on the recognition screen through a one-shot navigation argument. A successful `submitInput()` is the completed hearing-message seam. Replay can call `submitInput()` when the queue is empty, so that path must avoid recording a second turn.
- `RecognitionActivity.kt` already uses `lifecycleScope`, `Dispatchers.IO`, CameraX's single analysis executor, and `onStop`/`onDestroy` teardown. `AppHearSpeechPlayer.kt` uses `HttpURLConnection` and `org.json` off the main thread. `AndroidManifest.xml` has Internet permission. `build.gradle.kts` uses generated `BuildConfig` fields; `ui/settings/AppConfiguration.kt` exposes optional Supabase configuration, but no existing conversation or AI endpoint is present. No shared conversation state exists.
- The recognizer vocabulary has 236 exact glosses. In particular `I`, `ME`, `FINE`, `THANK-YOU`, `OKAY`, and `STORE` are absent; `GOOD`, `PLEASE`, `GO`, `HOME`, `SCHOOL`, and `SHOP1` exist. Phrase concepts must be validated against this exact manifest. Natural English text may contain grammatical words absent from the gloss sequence, but each claimed signed concept must have visual evidence.

## Integration decision

Use a process-local bounded conversation coordinator owned by the application, fed only after successful hearing `submitInput()` and committed recognition updates. Expose immutable Top-5 label/score evidence through the existing `FrameResult`; do not alter argmax, S8, or inference. Cache provider phrases once per hearing turn. At Hear, match the current event sequence against cached candidates using a conservative deterministic rule; on no match, use the unchanged raw S8 sentence. Keep the raw and assisted sequences distinct and log their event IDs for debug. A build-time flag defaults off; release behavior stays at baseline until an explicit rollout decision. The fake provider enables end-to-end offline tests; a remote provider remains isolated and fails open.

This is an application-side interpretation contract, not a new 378-feature or Recognition V2 schema. There is no F/S4 parity change. Software gates are deterministic matcher/fallback tests plus existing regressions; a phone smoke is an integration check, not an accuracy claim. Any accuracy claim later requires held-out cross-signer end-to-end evaluation per `context/eval-protocol.md`.

The existing ten-event continuous-phone diagnostic capture at `artifacts/recognition_upgrade/perception_vnext/recognition_utility_236_01/continuous_transition_readiness_01/device_capture/session_20260927T162103Z/events.jsonl` has Top-1 scores from 0.070 to 0.992. Its Top-1/Top-2 margins include 0.004 and 0.028 near ties, plus several margins above 0.3. That small, mixed-purpose sample justifies a conservative provisional gap rule, not calibrated confidence or an accuracy claim. The matcher policy lives in `android/app/src/main/assets/context_phrase_assist_policy.json`; it permits at most one changed event, requires a Top-5 alternative within 0.08 and at least 75% of Top-1's score, and rejects changes when Top-1 exceeds 0.60. These values need held-out conversation validation before product rollout.
